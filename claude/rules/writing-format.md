# 文章の体裁

このファイルの規則は、Claude がドキュメント（仕様書・設計判断・README など、ファイルとして書き起こす文書）、Confluence のページ、Jira のチケットとコメント、PR の説明とコメントを書くときに従う体裁の規則である。対話応答の体裁は、`~/.claude/CLAUDE.md` の「出力先ごとの体裁」に従う。ドキュメント・チケット・PR を書くときも、`~/.claude/CLAUDE.md` の「説明の原則」と「すべての出力先に共通する体裁」には従う。

## 文と段落

- 一つの段落は、おおむね 100〜200 字で、一つの話題を書き切る分量にする。
- 文末をコロンで終えず、句点で終える（例: 「次のファイルを読む：」ではなく「次のファイルを読む。」）。
- 本文は主述の揃った日本語の散文で書く。表・箇条書き・体言止めは、同じ種類の項目を並べるとき（手順の各段階、比較する案の各列）だけに使い、説明文の代わりに使わない。
- 一つの節の中に話題の違う段落が並んだら、話題ごとに節を分ける。
- 一つの節の本文は 200 字以内を目安にする。表とコードブロックは字数に含めない。本文が 400 字を超えたら、目的に要らない文を削るか、話題ごとに節を分ける。
- 散文中で「1点目」「2点目」「1つ目」「2つ目」のような順序付き列挙表現で複数項目を並べない。並列に説明したい項目が複数あるなら、項目ごとに見出しを付けて節に分ける。順序付き列挙表現を使うと、読み手は項目の区切りを文中から探さなければならず、見出しからの参照や目次への反映もできない。

## 見出しと節

- 見出しに章番号を付けない。章番号は、Confluence のような表示する側が付ける。
- ドキュメントの冒頭にタイトルを H1 として書かない。Confluence ではページタイトルを本文とは別の欄に入力するので、本文にもタイトルを書くと二重に表示される。本文の最上位の見出しは最初の節（概要など）の見出しにし、その見出しを H1 で書く。
- 節を分ける前に、何を基準に節を分けるか（作業の順番、変更した機能など）を決める。どの節にも入らない内容が出たら、「その他」の節を作らずに、節を分ける基準を決め直す。
- 各節には、その節の見出しが表す内容だけを書く。例えば「対処方針」という見出しの節には、対処の方針を書き、語の説明だけを並べた下位の節を置かない。

## 表

- 表のマスに条件（合格の条件、入力の条件など）を書くときは、「〜に収まること」のように「〜こと」で終わる名詞句にそろえる。

## PR のレビューへの返信

- Claude は、行に付いた指摘への返信を、その指摘のスレッドに付ける。
- レビューの本文のように、行に付いていない指摘が複数あるときは、Claude はそれぞれの指摘を引用したうえで、全部への返信を PR の 1 件のコメントにまとめる。
- 返信には、指摘を受けて何をどう直したかだけを書く。指摘の本文に書かれている経緯や、レビュアーが PR の説明で読んでいる経緯は、返信に書き直さない。
