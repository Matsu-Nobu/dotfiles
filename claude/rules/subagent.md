# サブエージェントに実装を任せるとき

実装作業は、メインの会話で Claude が自分で行うのが既定である（`~/.claude/CLAUDE.md` の「実装作業はメインの会話で進め、サブエージェントに任せない」）。このファイルの規則は、互いに独立した作業を複数同時に進める必要があるときか、ユーザーがサブエージェントを使うよう明示的に指示したときに、サブエージェントに実装を任せる場合に適用する。

サブエージェントは会話の文脈を受け取らないので、指示には、作業の目的、決まっている前提、触るファイル、完了の条件を書く。force-push のようなユーザーの承認が要る操作は、サブエージェントの中で済ませず、完了の報告を受けてからユーザーに承認を求める。

## 流す spec はファイルパスで指示に書く

サブエージェントへの指示には、 最後に流す spec をファイルパスで列挙する。 ディレクトリを指定しない。 範囲を決めさせると関連しそうなものを広く集め、 待ち時間が作業時間を支配する。

挙げるのは変更したファイルに対応する spec だけで、 その呼び出し元や周辺のディレクトリには広げない。 全体が壊れていないかは CI が全件を並列で流して確かめる。

ただし多くの箇所から呼ばれる基盤を変更したときは、 呼び出し元の spec を 1〜2 本だけ代表として加える。 全部を加えるのではなく、 呼び出し元が全滅する類の失敗を CI を待たずに拾うためのもの。
